## Build

The app ships as ONE self-contained HTML file (must run offline-capable from a phone or PC, no external assets). Source lives in `src/` (`index.html` with `<!--@include path-->` markers, `styles.css`, `js/*.js`). Never edit the built HTML by hand.

- `node build.mjs` runs the Reader self-test, then writes `dist/stream-visualizer.html` (dev build).
- `node build.mjs --release` writes the next `stream-visualizer_vNNN.html` in the repo root (never overwrites an existing version). Release after each finished step so the user always has an up-to-date single file.
- Publishing: the repo is public and `.github/workflows/pages.yml` serves the newest `stream-visualizer_vNNN.html` in the repo root as the GitHub Pages site (https://bandeiracaio.github.io/stream_visualizer/) on every push to `main`. So after `--release`, commit and push; unreleased `src/` work never goes live. Pages caches for about 10 minutes, so a phone may need a reload to see a new version.
- Line endings are mixed: `app.js`, `reader-episodes.js`, `reader-register.js`, `reader-tools.js` are CRLF, the rest LF. Edit without converting (Python `open(..., newline="")`), then check `git diff --stat`: a whole-file diff means the endings changed.
- Scope: each piece of work is its own step and its own release. UX steps leave the Reader engine, trading/paper-broker and feed logic alone; note anything else spotted instead of changing it. Feature steps (Overview, then the Reader redesign) may touch the engine, which must stay pure, DOM-free and replayable, with self-test scenarios added for new behaviour.
- Reader redesign direction (agreed): detect *episodes* (forming -> active -> fading -> ended, resumable) instead of one-off events; report detected time and back-dated start; multi-variable evidence checklist per episode; neutral participant language (aggressor / passive side), no bull/bear; first families: absorption, exhaustion, aggression burst, wall; validate with session record/replay, a span timeline, and agree/disagree labels.

- Self-revising Reader (specs in `.scratch/self-revising-reader/`, language in `CONTEXT.md`, decisions in `docs/adr/`): the Reader measures its own assumptions, flags drift, proposes threshold changes, and the user approves them. The register/drift/proposal code never changes a detection by itself; only an approved threshold does. Sigma (`sigmaBps`, the scale of normal price movement) and its static expectation are described in `docs/adr/0004` and `.scratch/self-revising-reader/04-sigma-scale.md`; old register files from before v012 are on the wrong scale. Before touching the episode layer's evidence cut-offs, byte-compare detections on simulated scenarios before and after (the refactors so far were proven this way).
- Weekly review: the user exports a review report and register from the Reader tab. Approving or resetting a threshold downloads a revision file; the user drops it into `docs/revisions/`. Before a release run `node fold.mjs --check`, then `node fold.mjs`, review the diff, `node build.mjs`, then `--release`. `fold.mjs` rewrites the matching defaults in `reader-engine.js` / `reader-episodes.js` and marks each file `Folded: yes`; it refuses a file that does not fit the current defaults.

## Source map

- `src/js/reader-drift.js` (pure): judges drift per variable from session summaries. `src/js/reader-proposals.js` (pure): percentile maps, threshold proposals, replay verdict. `src/js/reader-register.js` (pure): assumption register, baselines, sessions, drift history, proposals, approvals and overrides; fed by the engine. `LINKS` there maps each threshold to the quantity it is compared with.

- `src/js/reader-episodes.js` (pure): episode state machines and evidence checklists for absorption / exhaustion / burst / wall. Tunables in `READER_EPISODES.DEFAULTS` (also `READER.cfg.ep` at runtime). Recent detection changes: walls merge by price (`wallMergeBps`, `wallMergeMs`) and have a minimum size (`wallMinUsd`); exhaustion requires price near the extreme now (`exhNear`); flow z-scores use `zOtherFrac` and `zCap` (engine cfg). Fast and mid readings of one event are separate episodes on purpose; the groups layer (`groupGapMs`) presents them as one.
- `src/js/reader-engine.js` (pure): order-flow engine and the legacy one-off event detectors; drives the episode layer once a second. Recording is `startRecording({quoteMs})`; replay is `READER_ENGINE.replayEngine(inputs, cfg)`.
- `src/js/reader-landscape.js` (pure): grid maths for the Flow landscape (3D surface, playhead = time). `src/js/reader-landscape-view.js`: its drawing and controls; read-only, hooks `renderReader`, loaded last. Spec in `.scratch/flow-landscape/`.
- `src/js/reader-selftest.js`: simulator scenarios; the build runs them and fails if any fail. Add a scenario for any new engine behaviour.
- `src/js/overview.js`: Overview (home) view. `src/js/app.js`: feeds, charts, navigation, Reader cards. `src/js/reader-tools.js`: record/save/load/replay, threshold tuning, timeline, agree/disagree/missed labels (loaded last, called from `renderReader`).
- `src/js/auto-record-core.js` (pure, self-tested): volatility from the mark price and the start/stop decision of auto-record; `src/js/auto-record.js`: its view, loaded last. The price socket, reconnects and volatility reading run in a Web Worker built from `auto-record-core.js` + `auto-record-worker.js` (embedded in the page as `#arWorkerSrc`; falls back to the page's own socket), and armed pages hold a Web Lock `sv-armed`, and every auto-recording carries `pre` (the 30 minutes of mark price, one point a second, before the trigger, plus the trigger reading; `AUTOREC.dump`), because a hidden tab's timers are slowed and the page can be frozen (see the Health log). Spec in `.scratch/auto-record/`.
- `src/js/recordings.js`: Saved recordings (IndexedDB copy of every saved session; Share/Download/Open/Delete), loaded after auto-record. `src/js/status-core.js` (pure, self-tested): header status chips and the version comparison; `src/js/status-bar.js`: its view (chips next to Connect/Pause, "newer version" bar). `src/js/session-quality.js` (pure, self-tested): how complete a recording is (minutes with data, longest silence, clock rate); saved into every session file as `quality` (plus the page's `health` notes) and shown in Saved recordings. `src/js/collectors-core.js` (pure, self-tested; the object is `COLLECT`, not `COL`, which is the chart colours in app.js), `src/js/collectors-worker.js` (always-on Web Worker, embedded as `#colWorkerSrc`: derivatives context v055, calendar tags by rule v056) and, on the page while recording, the book depth summaries (v057, wraps `bnDepth` to watch updates; edges 1/5/10/20 bps), plus the extra venues (v058: Coinbase, Bybit, OKX, Binance spot and majors' marks, opened by the worker while a recording is on or auto-record is armed; an auto-recording's `ext` starts 30 minutes before the trigger, v063), and the Hyperliquid wallet layer (v059: the 10 biggest traders by traded notional, their positions and liquidation fills; addresses stay in data files), and Deribit options and volatility for BTC / ETH (v060: DVOL every 10 s, the option chain summarised every 120 s) and `src/js/collectors.js` (view, starts that worker): collectors write records `["c", name, t, payload]` to a rolling 24 h tape (IndexedDB `sv-tape`) and every saved session carries the matching slice as `ext`, beside `inputs`; the engine never sees them. Telemetry (v053) samples the page's feeds every 10 s while connected and the worker's price stream while armed. Spec: `.scratch/collectors/`. `src/js/health-log.js`: the Health log under Saved recordings, a black box kept in localStorage (tab hidden or frozen, timer gaps, computer sleep, page reopened, venue silent, price-stream drops, wake lock lost, learning restarted); read-only, loaded after status-bar.js. The build stamps `APP_VERSION` (`vNNN` for a release, `dev` otherwise); the page fetches `version.json` (written by the Pages workflow) to learn the newest release.
- Episode cards show collector context (v067): in an opened card, above "your call", a line of chips with what the collectors read when it was detected (`COLLECT.context` in `collectors-core.js`: each reading's deviation from its own previous 30 minutes, unusual at 1.5 standard deviations and a move worth seeing; `epCtxBar`, `colContextFor`, `colLabelCtx` at the end of `collectors.js`). Live it reads the last 75 minutes kept in memory (`CL.recent`); in a replay, the session's own `ext` (`rtReadSessionFile` keeps it; a recording made on the page gets it from the tape). Agree / disagree stores the same readings in the label as `ctx` (`{t, v:{feature:[value, deviation]}, liq:[binance, hyperliquid]}`), because the tape is pruned after 24 hours. `COLLECT.FEATURES` is the one list of features, shared with the analysis scripts. Display only: the engine, the episode layer and detections are untouched.
- `analyze-collectors.mjs` (repo root, offline, not part of the app; `--selftest` runs its own checks): reads downloaded tapes (`tape_*.json`) and saved sessions (`session_*.json.gz`) and prints per-collector coverage, the lead-in of an auto-recording, numeric fields that never change, and an evaluation of 21 features against the next 5 minutes of Binance mark volatility under a plan fixed in advance (`PLAN` in the script, `--plan` prints it): partial rank correlation controlling for the previous 5 minutes' volatility, circular-shift permutation p-values, a correction for the number of features, and a time split into a deciding half and a confirming half; `--merge` joins several tapes and sessions (identical records counted once). It takes record names and usual intervals from `COLLECT.OWNER` / `EXPECT_MS`, and the feature list `FEATURES` inside it needs a line for a new collector.
- `analyze-episodes.mjs` (repo root, offline, not part of the app; `--selftest`): replays saved sessions through the Reader engine (default thresholds, or `--cfg`), takes the episode groups, looks up what each collector read when each was detected (as a percentile against all collector data given; `--tape` adds reference data), and contrasts the groups you agreed with against those you disagreed with (`--labels reader_labels.json`, from Export labels) and the two most common outcomes of a family, with permutation p-values corrected for the number of features. Descriptive and small-sample: it says where to look, never keep or drop. Imports `FEATURES`, `readInput`, `rng` from `analyze-collectors.mjs`.
- Navigation (v068-v070, spec `.scratch/app-reorganization/spec.md`): six areas in `GROUPS` (app.js): Now (overview, charts, micro, viz, tape, market), Reader (reader = Episodes, signals), Review (replay, drift, assumptions), Recordings (record, saved, healthlog, collectors), Trade (trading, accounts, history, accinfo), System (streams, health, raw, engine). A view is what `data-tab` on a `<section>` names; `READER_VIEWS` lists the ones drawn by `renderReader`. Phone: fixed bottom bar; PC: left sidebar. The header status chips (`#liveChips`) live in Feed health. Messages from record/save/load/replay go to every `.rtmsg` element. The Overview is a read-only dashboard whose cards link into the areas.
- Order history and account info (v071-v073, spec `.scratch/order-history/spec.md`): `src/js/history-core.js` (pure, self-tested; object `HIST`): one row shape for orders / fills / income from Binance and the simulated broker, the account in the same shape, totals, 7-day pieces, merge, CSV columns. The paper broker keeps `SIM.log` (orders, fills, income; capped) beside its own arrays, which must not change. `src/js/account-info.js` (Trade > Account info) and `src/js/order-history.js` (Trade > History: Orders / Fills / Income, symbol, period, totals, CSV): read-only (GET only), load when opened or on Refresh, never on a timer; `logout` is wrapped to clear their caches. Both are display only. Real demo/live keys have not been tried; the Binance paths were tested with a stubbed `fetch`.
- Testing UI: serve `dist/` with `python -m http.server`, drive it with the Chrome tools; the window does not resize the viewport, so test phone width through a 390px iframe. Hidden tabs throttle requestAnimationFrame to ~1 fps, which makes rendering look stale.
