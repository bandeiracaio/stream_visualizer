# Offline studies and analysis scripts (reference)

Repo-root scripts, not part of the app. Each takes `--selftest`; the studies also take `--plan` / `--status`. Rules that apply to all of them are in `CLAUDE.md` (pre-registered studies).

## Scripts

- `analyze-collectors.mjs` (repo root, offline, not part of the app; `--selftest` runs its own checks): reads downloaded tapes (`tape_*.json`) and saved sessions (`session_*.json.gz`) and prints per-collector coverage, the lead-in of an auto-recording, numeric fields that never change, and an evaluation of 21 features against the next 5 minutes of Binance mark volatility under a plan fixed in advance (`PLAN` in the script, `--plan` prints it): partial rank correlation controlling for the previous 5 minutes' volatility, circular-shift permutation p-values, a correction for the number of features, and a time split into a deciding half and a confirming half; `--merge` joins several tapes and sessions (identical records counted once). It takes record names and usual intervals from `COLLECT.OWNER` / `EXPECT_MS` (derived from `COLLECT.REGISTRY`, see Structure below), and the feature list `FEATURES` inside it needs a line for a new collector.
- `analyze-episodes.mjs` (repo root, offline, not part of the app; `--selftest`): replays saved sessions through the Reader engine (default thresholds, or `--cfg`), takes the episode groups, looks up what each collector read when each was detected (as a percentile against all collector data given; `--tape` adds reference data), and contrasts the groups you agreed with against those you disagreed with (`--labels reader_labels.json`, from Export labels) and the two most common outcomes of a family, with permutation p-values corrected for the number of features. Descriptive and small-sample: it says where to look, never keep or drop. Imports `FEATURES`, `readInput`, `rng` from `analyze-collectors.mjs`.
- `compare-detections.mjs` (repo root, offline; `--selftest`): replays saved sessions through two versions of the Reader (working tree or any git revision via `--rev-a` / `--rev-b`, plus `--cfg-a` / `--cfg-b`) and reports every difference in the episode groups and signals as exact JSON; exit code 1 when anything differs. This is the check for "byte-compare detections before and after" (`--rev-a HEAD` compares your edit with the last commit). `reader-scoreboard.mjs` (repo root, offline; `--selftest`): per family, the price move after detection at 1 / 5 / 15 minutes in sigmas (signed in the side's direction, beside the typical |move| at random moments), precision (agree / (agree + disagree), Wilson interval, per day) and recall among what you called real (agree + missed, a missed label counts as found when the replay now has a matching group; try `--cfg`). Descriptive and small-sample; a rate with fewer than 8 labelled groups is not shown. Both import `readInput` from `analyze-collectors.mjs`; the scoreboard also uses `labelMatches` / `labelFor` from `analyze-episodes.mjs` and `loadEngine` from `compare-detections.mjs`.
- `reader-robustness.mjs` (repo root, offline; `--selftest`): the randomized-parameter test. Keeps the saved sessions fixed, draws many configurations with the episode thresholds each scaled by a random factor within `--spread` (default 25%, seeded; `--cfg` sets the centre, e.g. a proposed threshold), replays every session under each, and shows per family the base value and the 5th / 50th / 95th percentile of group count, forward move (sigmas) and precision (`--labels`), plus the share of runs that hold. A result that survives is not hanging on exact threshold values; a collapse means it is. Descriptive, never changes a detection. Reuses `scoreboard` and `loadEngine`. Slow (one replay per session per run): start with few sessions or `--runs 20`.
- `analyze-wallets.mjs` (repo root, offline; `--selftest`, `--plan`): the pre-registered wallet study (plan `.scratch/wallet-study/plan.md`, registered 2026-11-05 before the first run on real sessions). Reads saved sessions, learns two wallet classes (persistent, hot by 10 s markout) on the first 40% of recorded hours, and tests 11 features of Hyperliquid taker wallets per 5-minute window against the next 5-minute move (sigmas) on the next 30% (decide, Holm-corrected) and last 30% (confirm). Uses `readInput` / `rng` from `analyze-collectors.mjs` and `sigmaOf` / `forwardMove` from `src/js/scoreboard-core.js`. Run it ONCE on real sessions; a change to the plan is an amendment in the plan file.
- `analyze-wallets-persistence.mjs` (repo root, offline, exploratory; `--selftest`): follow-up to the wallet study that asks whether wallets with a good 10-second markout in block A stay good in B + C (rank correlation, hot cohort against random cohorts, deciles, baseline A first half -> second half). Written after the registered result; see `.scratch/wallet-study/persistence-20261105.md`.
- `analyze-liquidations.mjs` (repo root, offline; `--selftest`, `--status`, `--plan`): the pre-registered liquidation reversal study (plan `.scratch/liquidation-study/plan.md`, registered 2026-11-06 before any test-set session existed). Only sessions that started after the plan's cutoff count (the 166 earlier sessions are the exploration set: their outcomes were seen). `--status` prints counts only (test sessions, clusters, pairs) and no outcome, so progress can be watched; the test itself runs once, when the three-venue variant has 60 clusters and 30 pairs. Uses `LIQ` (`src/js/liq-core.js`) and the Scoreboard's `sigmaOf` / `forwardMove`; Bybit and OKX liquidations come from the `liqPerp` records (v122 and later).
- `panel-label.mjs` (repo root, offline; `--selftest`): panel labelling for triage. `packets` builds blinded packets of episode groups (no outcome, resolution, stage, absolute time or price after the end) and a shuffled file per voter; subagent voters each write `votes_N.json`; `tally` counts a group real / not-real only when the voters are unanimous, otherwise contested (`--agree N` relaxes that), and writes `panel_labels.json` (`src: "panel"`, never merged into the user's labels). The wording the voters get is `RUBRIC` in the script (a wall counts only if it held and was tested or price reacted). Output goes to `panel/` (gitignored). Not validated against the user's labels yet.
- `sample-designs.mjs` and `design-harness.mjs` (repo root, offline; `--selftest`): the trade-system Monte Carlo study. The sampler draws trade-system designs from the pool `.scratch/trade-system/mapping-v3.csv`; the harness replays one design (one trigger, one exit, one stop) on saved sessions. Spec: `.scratch/trade-system/sampling-design.md`.
- `venue-volume-history.mjs` (repo root, offline, no release needed): downloads free public historical BTC trade data (no accounts or keys) and prints per-venue volume.
