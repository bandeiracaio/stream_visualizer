# Source map

Reference, read when you touch that area. Specs are in `.scratch/<feature>/`, decisions in `docs/adr/`, terms in `CONTEXT.md`. The terms **pure** and **display only** are defined in `CLAUDE.md`.

Pure files (checked: no DOM, storage or socket use): every `*-core.js`, `hooks.js`, `views.js`, `session-quality.js`, and the Reader engine files `reader-drift`, `reader-proposals`, `reader-register`, `reader-episodes`, `reader-engine`, `reader-landscape`, `reader-review`, `reader-selftest`, and `broker.js` (it fetches and signs only through injected functions). Every other file touches the page.

## Seams

- `src/js/hooks.js` (`HOOKS.on(name, fn)` / `HOOKS.emit(name, ...args)`): the way a late-loaded module extends an owner's function. Names: `renderReader` (end of `renderReader`), `renderAccount` (end of `renderAccount`), `logout` (end of `logout`), `liquidation` (emitted by `futures-view.js`), `bnDepth` (start of `bnDepth`, before the book applies it; no subscriber since the book collector moved to the worker). Subscribers run in script-load order; an error in one is logged and contained.
- `src/js/views.js` (`VIEWS`): the registry of views. `VIEWS.area(id, label, icon)` declares a navigation area with its icon path (`VIEWS.icons()` feeds `GICON`); `VIEWS.register({id, label, area, slot?, minIntervalMs?, render?, onOpen?})` adds a view (registration order = display order). Views with the same `slot` share one render and one throttle; the frame loop calls `VIEWS.tick`. `VIEWS.onOpen(id, fn)` adds an open action from a later module; `setTab` calls `VIEWS.open`. Outside the registry: the dirty-flag block (market / tape / raw) and `renderSlow` (1 s).

## Reader

- `src/js/reader-engine.js`: order-flow engine and the legacy one-off event detectors; drives the episode layer once a second. Recording is `startRecording({quoteMs})`; replay is `READER_ENGINE.replayEngine(inputs, cfg)`.
- `src/js/reader-episodes.js`: episode state machines and evidence checklists for absorption / exhaustion / burst / wall. Tunables in `READER_EPISODES.DEFAULTS` (also `READER.cfg.ep` at runtime). Fast and mid readings of one event are separate episodes on purpose; the groups layer (`groupGapMs`) presents them as one.
- Self-revising Reader (specs `.scratch/self-revising-reader/`; sigma (`sigmaBps`) in `docs/adr/0004` and `.scratch/self-revising-reader/04-sigma-scale.md`): the Reader measures its own assumptions, flags drift, proposes threshold changes, and the user approves them.
  - `src/js/reader-drift.js` judges drift per variable from session summaries. `src/js/reader-proposals.js`: percentile maps, threshold proposals, replay verdict.
  - `src/js/reader-register.js`: assumption register, baselines, sessions, drift history, proposals, approvals and overrides; fed by the engine. `LINKS` there maps each threshold to the quantity it is compared with.
  - `src/js/reader-review.js` (`READER_REVIEW`): the weekly-review decisions (replay plan and config, label tally, verdicts, freshness, revision / revert file text, imported-override filter, apply / read a threshold). The revision-file text is the format `fold.mjs` reads (ADR 0003): do not change it casually.
- `src/js/reader-tools.js` (loaded late, called from `renderReader`): record / save / load / replay, threshold tuning, timeline, agree / disagree / missed labels. It keeps the replay loop, timers, downloads, `localStorage` and rendering for `reader-review.js`.
- Flow landscape: `src/js/reader-landscape.js` is the grid maths (3D surface, playhead = time); `src/js/reader-landscape-view.js` draws it and holds the controls (read-only, hooks `renderReader`, loaded last). Spec `.scratch/flow-landscape/`.
- Label queue (spec `.scratch/label-queue/spec.md`): `src/js/label-queue-core.js` (`LABELQ`: oldest-first order of unlabelled groups, next / previous pick that wraps) and `src/js/label-queue.js` (prev / next unlabelled and "next after a label" above the Timeline detail; keys N / P / arrows / A / D). Navigation only: a label is made by the existing buttons in `reader-tools.js`, in the same format.
- Scoreboard (spec `.scratch/scoreboard-view/spec.md`): `src/js/scoreboard-core.js` (`SCOREBOARD.sessionPart` replays one session, `SCOREBOARD.summarize` applies labels; label matching is injected) is loaded by both `reader-scoreboard.mjs` and `src/js/scoreboard-view.js`. The view (Review > Scoreboard) replays the Saved recordings with the current thresholds when you press Compute (results kept per file and settings); labels come from `RT.labels`. Display only.
- `src/js/reader-selftest.js`: simulator scenarios; the build runs them and fails if any fail. A new engine behaviour gets a scenario here.

## App shell

- `src/js/app.js`: charts, navigation, account state (`ACC`), the sim wrappers, `placeOrder` and the page timers. The rest of what used to live there is in deep modules behind small interfaces (v127, display only; see below).
  - `src/js/paper-broker-core.js` (`PAPER`, pure): the paper broker. State, symbol, clock and quotes (`ctx = {sym, now, q:{bid, ask, mark}}`) are passed in; functions mutate the `SIM`-shaped state in place (same shape `account-info.js` / `order-history.js` read) and return data, never text. Fees 0.0002 maker / 0.0005 taker. `app.js` keeps thin `sim*` wrappers and `simCtx()`, which supplies `accSym()`, `Date.now()` and `M.bnBid/bnAsk/bnMark`. Self-tests prefixed `paper broker:`.
  - `src/js/broker.js` (`BROKER`): the broker seam. `BROKER.sim(deps)` and `BROKER.binance(deps)` both give `place(order)`, `cancel(id)`, `cancelAll()` (this asset only) and `snapshot()`; signing / fetch and the sim wrappers are injected. Validation (filter rounding, minimums, the live cap) and the live `confirm()` stay above the seam in `placeOrder`: validate, confirm, `broker().place`. `ACC`, the 3 s live refresh and `refreshSoon` are unchanged. Self-tests `broker:` use a stubbed `signed`; no real Binance request has been made through it yet.
  - `src/js/micro-core.js` (`MICRO`, pure): microstructure data (`topN`, `imbalance`, `heatSnap`, `microprice`, sweep grouping: same ms and side is one sweep). `MICRO.create({onSweep})` holds the state; `app.js` owns one instance `MI` (`MI.hist`, `MI.heatBn`, `MI.heatHl`, `MI.sweeps`) and the 250 ms timers, and the `draw*` / `render*` functions read it. `futures-view.js` reads `MI.heatBn` / `MI.heatHl`. Self-tests `micro:`.
  - `src/js/market-core.js` (`MARKET`, pure): the history invariants (5-minute `KEEP` window, 250 ms mid row, 500 ms cvd row, trade bookkeeping, reset values). `app.js` still owns the live objects `M`, `trades`, `cvd`, `cvdHist`, `midHist`, `health`, so every reader is unchanged; writers go through `MARKET`. Not done on purpose: `feeds.js` still assigns `M.x` directly and increments `health.*`. Who writes what: `.scratch/market-store/map.md`. Self-tests `market:`.
  - `src/js/trading-view.js` (page): the Trading layout (module catalog, `addModule`, order ticket, `renderTrading`; `tradingInit()` is called from `app.js` at startup). `src/js/reader-cards.js` (page): Reader episode cards (`epCard`, `epWho`, `epEvidence`, `renderEpisodes` (hides a wall card younger than `epFilter.minWallMs`, display only; the header select `epMinAge`, saved under `epMinAge`), `rdFilter`, `epFilter`, `rdView` / `RD`). Both load before `app.js`; `renderReader` stays in `app.js`.
  - `src/js/overview.js`: the Overview (home) view, a read-only dashboard whose cards link into the areas.
- `src/js/feeds.js` (loaded before `app.js`; moved verbatim out of it): the market-reader instance and hooks, the Binance and Hyperliquid socket handlers and book maintenance. It reads and writes `app.js` globals (`M`, `S`, `addTrade`, the DOM) by name, and `collectors.js` / `arm-mode.js` reach `bnBook`, `hlBookT`, `HL.ev`. This is a locality move, not a narrow interface, because there is no second source to put behind one.
- Navigation (spec `.scratch/app-reorganization/spec.md`): six areas (`GROUPS`, built from `VIEWS.area` / `VIEWS.register` in `app.js`): Now (overview, charts, micro, viz, tape, market), Reader (reader = Episodes, signals), Review (replay, drift, assumptions), Recordings (record, saved, healthlog, collectors), Trade (trading, history), System (streams, health, raw, engine). A view is what `data-tab` on a `<section>` names; every view is one `VIEWS.register` in `app.js`, and the ten that share `slot:"reader"` are drawn by `renderReader`. Phone: fixed bottom bar; PC: left sidebar. The header status chips (`#liveChips`) live in Feed health. Messages from record / save / load / replay go to every `.rtmsg` element.
- Order history and account info (spec `.scratch/order-history/spec.md`): `src/js/history-core.js` (`HIST`): one row shape for orders / fills / income from Binance and the simulated broker, the account in the same shape, totals, 7-day pieces, merge, CSV columns. The paper broker keeps `SIM.log` (orders, fills, income; capped) beside its own arrays, which stay as they are. `src/js/account-info.js` (header Account panel, left half of the button) and `src/js/order-history.js` (Trade > History: Orders / Fills / Income, symbol, period, totals, CSV) are read-only (GET only), load when opened or on Refresh and never on a timer, clear their caches on the `logout` hook and load on `VIEWS.onOpen`. Display only. The Binance paths were tested with a stubbed `fetch`.

### Header

- Account split button (`#accSplit`, `src/js/account-button.js`): a left half (the account info panel, or the connect panel when nothing is connected; shows mode and unrealised PnL) and a caret (switch / connect panel). The panels are `section.accpanel` elements in `header` holding the old content with the same element ids; `HOOKS` name `renderAccount`. On a phone the button is one coloured letter (S / D / L, + when not connected) so the header stays two rows. Any button with `data-acc-open="info|switch"` opens an account panel (delegated in `account-button.js`; a direct `onclick` is closed again by the document click handler). The Overview account card shows the mode and has details / switch buttons. The broker and `ACC` are untouched.
- Status button (`#stBtn`, `src/js/status-button.js`): one button with a coloured dot per venue (BN / HL; `data-st` is set by `sbPills` in `status-bar.js`, the full text stays in the title and for screen readers) and an alert badge (count of warn / bad chips, border orange or red; info chips stay in the panel). Its panel `#stPanel` holds the venue texts (`#bnState`, `#hlState`) and all live chips (`#stChips`, written by `sbRender` beside `#liveChips`).
- Record and Arm are one joined pair (`.seg`; ids and handlers unchanged, Arm's on-state stays visible). The answer to Arm (`#arHdrMsg`) floats under the header.
- `src/js/keyboard-lock.js`: the 🐱 `#catLock` button beside the status button swallows every key until it is clicked again.
- `src/js/status-core.js`: header status chips and the version comparison. A save-folder chip ("save folder needs OK" / "last save failed" / "no save folder") shows only while armed or recording; `sbSnapshot` reads `FS` from `folder-save.js` and re-queries the folder permission every 30 s while armed. `src/js/status-bar.js` is its view (chips next to Connect / Pause, the "newer version" bar). The build stamps `APP_VERSION` (`vNNN` for a release, `dev` otherwise); the page fetches `version.json` (written by the Pages workflow) to learn the newest release.

### Look

Spec `.scratch/restyle/spec.md` (the "Terminal" direction: flat, monospace, amber headings). The token and contrast rules are in `CLAUDE.md`; a control's border is `--edge` and text on a fill is dark `--ink`. The chart canvases read the tokens through `TH` at the top of `app.js`: `TH.dim` axis text, `TH.text` / `TH.hi` lines and labels, `TH.line` grid, `TH.edge` axes, `TH.ink` text on a fill, `TH.canvas` background, `TH.a(name, alpha)` for rgba, and buy / sell / bn / hl / warn / accent. The category palettes (episode families `RT_COLORS`, raw-log stream colours `LOG_COLOR`, the heat, fan and waterfall scales) are literals on purpose; each is at least 3:1 (4.5:1 for text) against the chart background. Phone header size and button padding: `CLAUDE.md` and `docs/agents/testing-ui.md`.

## Arm mode

- Overnight run (spec `.scratch/overnight/spec.md`): Now > Arm mode has two sections. "Ready to arm?" (`OVERNIGHT.preflight` in `src/js/overnight-core.js`): online, newest version, save folder, disk, persistent storage, power (`getBattery`), wake lock API, tab visible, collectors, feeds disconnected, armed; each item ok / warn / bad with the fix. "Last night" (`OVERNIGHT.morning`): saved recordings of the last 12 / 24 / 48 h with their quality, collectors with holes, Health log problem notes, Open (to the replay) and "Count episodes to label" (replays the window with the current thresholds; the cache `SBV.parts` and `sbvPartFor` are shared with the Scoreboard view). `src/js/overnight-view.js` is the view, loaded after `scoreboard-view.js`. `OVERNIGHT.coverage` feeds the "Hours recorded" grid in Recordings > Saved recordings (`rcCoverage` in `recordings.js`). Display only.
- Re-arm prompt (spec `.scratch/arm-memory/spec.md`): an armed page keeps `ar.armed` (since, last seen, recordings) in the browser's storage; a page that loads and finds it while not armed shows the `#armBar` bar under the header (Re-arm now / Dismiss) and notes `armed page ended` in the Health log. A Disarm or a finished arming clears the flag at that moment; no bar while another page holds the `sv-armed` Web Lock. `src/js/arm-memory-core.js` (`ARMMEM`) and `src/js/arm-memory.js` (view). Auto-record is untouched.
- Disk space (spec `.scratch/arm-mode/spec.md`): `src/js/disk-core.js` (`DISK`, rates the room left) and `src/js/disk-watch.js` (`DW`, the once-a-minute reading for the Arm mode screen); `arm-mode.js` reads `DW` through a `typeof` guard.

## Recording

- Auto-record: `src/js/auto-record-core.js` (volatility from the mark price and the start / stop decision) and `src/js/auto-record.js` (its view, loaded last). The price socket, reconnects and volatility reading run in a Web Worker built from `auto-record-core.js` + `auto-record-worker.js` (embedded in the page as `#arWorkerSrc`; falls back to the page's own socket). Armed pages hold a Web Lock `sv-armed`. Every auto-recording carries `pre` (the 30 minutes of mark price, one point a second, before the trigger, plus the trigger reading; `AUTOREC.dump`), because a hidden tab's timers are slowed and the page can be frozen. Spec `.scratch/auto-record/`.
- `src/js/recordings.js` (loaded after auto-record): Saved recordings, an IndexedDB copy of every saved session (Share / Download / Open / Delete), and the "Hours recorded" grid (one cell per hour, `rcCoverage`).
- Session quality: `src/js/session-quality.js` rates how complete a recording is (minutes with data, longest silence, clock rate); saved into every session file as `quality` (plus the page's `health` notes) and shown in Saved recordings. `quality.collectors` says, per collector that was switched on (`colExpected` in `collectors.js`), how many records it wrote during the recording itself (from the trigger, so not the lead-in), the minutes with one and the longest silence (`SQ.collectors`; state none / holes / ok; holes = silence over three times its usual interval, at least 30 s; a collector writing less often than a third of the window, e.g. calendar, is not judged). `SQ.clean` (inputs and collectors) drives the warning colour; `quality.verdict` is unchanged. Files from before v111 have no `collectors`.
- Health log (`src/js/health-log.js`, loaded after `status-bar.js`; under Saved recordings): a read-only black box in `localStorage` (400 events) for tab hidden or frozen, timer gaps, computer sleep, page reopened, venue silent, price-stream drops, wake lock lost, learning restarted, and the workers' collector errors and "socket closed" notes (see Collectors).

## Collectors

Spec `.scratch/collectors/`. The object is `COLLECT` (not `COL`, which is the chart colours in `app.js`).

- `src/js/collectors-core.js` (`COLLECT`): `COLLECT.REGISTRY` has one entry per collector (`id`, `owner` page / worker, `expectMs`, `records`, `features`, `info`); `OWNER`, `EXPECT_MS`, `FEATURES`, `FEATURE_INFO` are derived from it. A new collector is one `REGISTRY` entry plus one `CONTRIB` entry, and its features also go in `FEATURE_ORDER` (a self-test fails otherwise; the order is fixed because analysis plans depend on it). `COLLECT.FEATURES` is the one list of features, shared with the analysis scripts.
- `src/js/collectors.js` (view; starts the worker): records are `["c", name, t, payload]`, written to a rolling 24 h tape (IndexedDB `sv-tape`). Every saved session carries the matching slice as `ext`, beside `inputs`; the engine never sees them. Telemetry samples the page's feeds every 10 s while connected and the worker's price stream while armed.
- `src/js/collectors-worker.js` (always-on Web Worker, embedded as `#colWorkerSrc`): derivatives context and calendar tags by rule, plus the collectors below.
  - Book depth summaries (edges 1 / 5 / 10 / 20 bps): since v107 the worker keeps its own Binance book (REST snapshot + diff stream, `COLLECT.perpBook("bn")`) and Hyperliquid book (socket + bucketed `l2Book` every 2 s, `COLLECT.hlBookSummary`) while a recording is on, one `bookBn` / `bookHl` record a second, so a hidden tab no longer starves it; the page only sends `recording` in the worker's start / rec messages.
  - Extra venues (Coinbase, Bybit, OKX, Binance spot and majors' marks): opened while a recording is on or auto-record is armed; an auto-recording's `ext` starts 30 minutes before the trigger.
  - Hyperliquid wallet layer: the 10 biggest traders by traded notional, their positions and liquidation fills; addresses stay in data files.
  - Deribit options and volatility for BTC / ETH: DVOL every 10 s, the option chain summarised every 120 s.
  - Perp flow (spec `.scratch/perp-flow/spec.md`): collector `perpFlow` (fast: only while recording or armed) records Bybit and OKX liquidations (`liqPerp`: every one, side of the forced order, bankruptcy price, coin) and each venue's open interest every 10 s (`oiPerp`), from two sockets; `COLLECT.perpFlowSubs` / `COLLECT.perpFlow`. No features yet. OKX announced its websocket port 8443 will be retired: `perpFlow` and the book collector use the plain URL (443); `venueSubs` and `tradeSubs` in `collectors-core.js` still use `:8443`.
- Socket close log (`COLLECT.sockWatch`; research `.scratch/socket-reconnects/research.md`): used by `collectors-worker.js` and `auto-record-worker.js`. `watch(name, socket)` writes a "socket closed" note to the Health log on every close that was not collection ending: close code, `clean`, reason, `upMs`, `silentMs`, `msgs`, and `ours` (why our own code closed it through `shut(socket, why)`: `silent` = a silence check, `page` = the page asked; empty = the server or network). A source writes at most 5 notes an hour and the next one carries `left_out`. The auto-record page forwards the worker's note to `hlNote`. The page's own fallback price socket in `auto-record.js` still logs only `upMs` / `silentMs`.
- Episode cards show collector context: in an opened card, above "your call", a line of chips with what the collectors read when it was detected (`COLLECT.context`: each reading's deviation from its own previous 30 minutes, unusual at 1.5 standard deviations and a move worth seeing; `epCtxBar`, `colContextFor`, `colLabelCtx` at the end of `collectors.js`). Live it reads the last 75 minutes kept in memory (`CL.recent`); in a replay, the session's own `ext` (`rtReadSessionFile` keeps it; a recording made on the page gets it from the tape). Agree / disagree stores the same readings in the label as `ctx` (`{t, v:{feature:[value, deviation]}, liq:[binance, hyperliquid]}`), because the tape is pruned after 24 hours. Display only: the engine, the episode layer and detections are untouched.

## Market views

- Futures stack (Now > Futures stack, from a trader's post: liquidations + volume delta + open interest under price). Display only; engine, feeds and broker untouched.
  - `src/js/futures-core.js` (`FUTSTACK`): 5 s bins per venue, `aggregate`, `highlights` (a liquidation spike confirmed by same-side delta and falling open interest), `reading` (the four delta x open-interest readings), `FUTSTACK.profile`, `FUTSTACK.parseLiq`, `FUTSTACK.backfill`. `futuresRender.store` is the test hook.
  - `src/js/futures-view.js`: the canvas, with cyan `--mark` boxes, a hover readout, the volume profile on the right (backfilled minutes are spread evenly over their high-low range, so approximate), a Bar Stats strip (delta share, open interest change, volume, trades, range per candle), an open interest line coloured by direction, and Buy now / Sell now / Close through `placeOrder`.
  - History: its own 4 h, not persisted, backfilled on every connect from Binance klines (1 m, taker buy volume = delta) and openInterestHist (5 m) via `FUTSTACK.backfill`; live data wins; no liquidation history.
  - Venues: liquidations from Binance (the app feed), Bybit and OKX (own sockets opened by the view while connected; Hyperliquid's feed flags none). Bybit / OKX also add open interest (polled every 10 s, one side, in coin: Bybit `singleOpenInterest`, OKX `oiCcy`; Bybit has 5 m history, OKX history is CORS-blocked in a browser so it is live only). The checkbox `all venues: liq + OI` sums them; a venue joins the sum only if it has a reading in the first 10% of the window. Price, delta, book and heatmap stay Binance / Hyperliquid.
- Liquidations readout (notes `.scratch/liquidation-study/exploration-20261105.md`): Now > Market and tape has a Liquidations section: Binance, Bybit and OKX liquidations as clusters (events within 30 s), per-venue dollars for 15 minutes, a 30-minute one-minute bar strip, and per cluster the Binance-mid move before (5 min) and after (1 min, 5 min) in sigmas, signed in the direction the forced orders pushed. `src/js/liq-core.js` (`LIQ`) and `src/js/liq-readout.js` (view, one-second render only while the tab is open). The events come through the hook `liquidation` (emitted in `futures-view.js` for the page's Binance feed and its Bybit / OKX sockets, so they exist only while the app is connected); `futuresRender.lq` exposes the socket states read-only. Display only: no socket of its own, nothing recorded.
